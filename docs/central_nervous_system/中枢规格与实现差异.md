# 中枢规格与实现差异

> 对比 `docs/central_nervous_system/中枢.md`（PDF 整理的规格）与现有代码实现的逻辑差异，用于基于现有算法完善规则。
>
> 优先级标注：🔴 重大（规格核心规则缺失/偏离，影响结构正确性） 🟡 中等（语义偏差，影响判定精度） 🟢 轻微（实现额外扩展或细节差异）。
>
> 代码行号基于当前工作区，仅供定位参考。

## 0. 优先级总览

| 领域 | 重大差距（🔴） | 中等差距（🟡） |
|---|---|---|
| 中枢构造与形态演变 | ① normal 默认 2 笔构造（规格要求 3 个次级别走势）；② 无 9 段扩展升级；③ 无中枢新生（3 买触发）；④ 扩张缺 3 买/原中枢结束判定且不跨线段 | 延伸无段数边界；构造相切不成立（比规格严）；扩展/扩张不区分 |
| 背驰与买卖点 | ⑤ 盘整背驰 T1P 不经过中枢；⑥ 无黄白线（DIF/DEA）算法；⑦ 趋势背驰默认未要求 ≥2 中枢 | 默认 macd_algo=peak 非面积；AREA 为半面积非整段；进出笔未校验同方向/已走完；二买用回撤率非"不创新高低"；盘背三形态未联动 |
| 线段终结与特征序列 | ⑧ 线段终结完全未结合背驰/盘背（"快了半拍"未解决）；⑨ 无第一/第二特征序列双序列概念 | 第一二元素未禁止包含（与规格相反）；顶底两侧无包含约束；无趋势/盘整线段分类终结分支 |

## 1. 中枢构造与形态演变

### 🔴 1.1 中枢构造笔数：normal 默认 2 笔，规格要求 3 个次级别走势

- **规格**（中枢.md §1.1）：中枢 = 连续 **3 个**次级别走势相重叠的部分。
- **现状**：`ZS/ZSList.py:73-89` `try_construct_zs`，`normal` 模式默认取 `lst[-2:]`（2 笔）；`one_bi_zs=True` 甚至 1 笔即可构造。仅 `over_seg` 模式取 3 笔。
- **差距**：默认 normal 模式与规格"3 个次级别走势"不一致。实现用 2 笔重叠即成中枢，构造门槛低于规格。
- **完善建议**：区分"3 段重叠成中枢"的硬约束与"一笔中枢"的扩展开关；如需保留 2 笔/1 笔中枢作为实战扩展，应在配置中显式标注其偏离规格，并默认按 3 段构造。

### 🟡 1.2 构造相切不成立（比规格更严）

- **规格**（§1.4）：上界 ≥ 下界即成立（含等于）。
- **现状**：`ZSList.py:89` `min_high > max_low`（严格大于），相切（等于）时不构造。
- **差距**：实现比规格更严格。
- **完善建议**：评估是否放开为 `>=`，或在规格侧确认"相切不算重叠"的口径（规格原文未明确相切情形，需对照原图确认）。

### 🔴 1.3 无 9 段扩展升级逻辑

- **规格**（§2.3）：次级别累计达 **9 段** → 升级为高级别中枢（原中枢未结束、无 3 买）。
- **现状**：`ZS/ZS.py`、`ZSList.py` 中无任何段数计数与级别升级逻辑。`try_add_to_end`（`ZS.py:148-154`）逐笔延伸无段数上限，也无 9 段阈值。
- **差距**：规格的核心升级规则完全缺失。
- **完善建议**：在中枢延伸过程中计数次级别段数，达 9 段时触发升级（生成高级别中枢，原中枢记入 sub_zs_lst 或独立升级标记）。

### 🔴 1.4 无中枢新生（3 买触发）逻辑

- **规格**（§2.1）：原中枢出现 3 买/卖 → 在上方/下方形成新同向中枢，原中枢结束。
- **现状**：代码无 3 买触发中枢结束/新生的判断；新中枢仅因区间不重合自然形成，与 3 买无关。
- **差距**：规格"新生=原中枢 3 买后产生新中枢"的因果链未实现。
- **完善建议**：在 bsp3 产生时标记原中枢结束，并据此识别"新生"中枢（区别于"延伸形成的第二中枢"）。

### 🔴 1.5 中枢扩张：peak 模式形态相似但缺核心判定，且不跨线段

- **规格**（§2.4）：两个同向中枢的震荡区间重合 → 升级（原中枢已结束、有 3 买）。
- **现状**：`ZS/ZS.py:115-132` `combine` 的 `peak` 模式用 `peak_low/peak_high` 重叠判断，形态上近似扩张，但：
  - (a) `ZS.py:118-119` 要求 `begin_bi.seg_idx` 相同，**仅同线段内合并、不跨线段**；
  - (b) 不检查 3 买；
  - (c) 不检查原中枢是否结束；
  - (d) 合并为"一个中枢 + sub_zs_lst"，非升级到高级别。
- **差距**：peak 合并仅形态相似，缺规格的核心判定条件；跨线段的扩张在 normal 模式下不会发生。
- **完善建议**：新增"扩张"判定路径——跨线段、要求前中枢已结束、要求有 3 买、震荡区间重合 → 升级为高级别中枢。

### 🟡 1.6 延伸无段数边界、无与扩展的衔接

- **规格**（§2.2）：第 4~8 段为延伸/震荡，达 9 段升级为扩展。
- **现状**：`try_add_to_end` 只要 `in_range` 即延伸，无 4~8 段范围、无段数上限、无与 9 段升级的衔接。
- **完善建议**：延伸段数计数，9 段为扩展升级阈值（与 1.3 联动）。

### 🟡 1.7 扩展 vs 扩张未区分

- **规格**（§2.5）：扩展（原中枢未结束、无 3 买、9 段触发）vs 扩张（原中枢已结束、有 3 买、震荡重合）。
- **现状**：`zs`/`peak` 两种 `combine_mode` 仅按区间/peak 重叠合并，不区分两种情况，无 3 买/结束判断。
- **完善建议**：用 3 买 + 原中枢结束状态作为分流条件，分别走扩展/扩张升级路径。

### 🟢 1.8 实现有但规格未提的扩展

- `zs_algo` 三模式（normal/over_seg/auto）：实现自有扩展，规格无此概念。
- `over_seg` 要求构造首笔方向与 `parent_seg.dir` 相反（`ZSList.py:80-86`）：规格无此概念。
- 禁止第一笔是中枢起点（`ZSList.py:44` `begin_bi.idx > 0`）：实现额外限制，规格未提。
- 中枢合并需同一线段内（`ZS.py:118-119`）：实现限制，规格未提，且导致跨线段扩张不会发生（见 1.5）。

## 2. 背驰与买卖点

### 🔴 2.1 盘整背驰 T1P 不经过中枢

- **规格**（§4.4、§5.1）：盘整背驰前提是**有中枢**（1 个中枢），离开中枢段力度 < 进入中枢段。
- **现状**：`BuySellPoint/BSPointList.py:191-213` `treat_pz_bsp1`（T1P）取 `last_bi=seg.end_bi`、`pre_bi=bi_list[last_bi.idx-2]`（前同向笔），直接比较相邻两同向笔 MACD 力度，**完全不经过中枢**。
- **差距**：盘整背驰未使用中枢，与规格"必须有中枢"不符；T1P 实为相邻笔力度比较。
- **完善建议**：T1P 应改为基于盘整中枢的进/出中枢笔比较（与 T1 同结构、仅中枢数量不同），而非相邻笔。

### 🔴 2.2 无黄白线（DIF/DEA）算法

- **规格**（§4.7）：黄白线背驰 = 出中枢段黄白线高度/低度弱于进中枢段；面积为主、黄白线辅助，两者一致更可靠。
- **现状**：`Bi/Bi.py:189-215` `cal_macd_metric` 的所有算法均基于 MACD 柱或价格/量，**无任何黄白线（DIF/DEA）算法**。`Cal_MACD_diff`（`Bi.py:291-304`）名字像但实为"MACD 柱 max-min"。`MACD_ALGO` 枚举无 DIF/DEA 项。
- **差距**：规格的"黄白线辅助确认"完全缺失，无法做"面积 + 黄白线"双重确认。
- **完善建议**：新增 DIF/DEA 高低比较的 macd_algo；支持"主算法（面积）+ 辅算法（黄白线）"双确认机制。

### 🔴 2.3 趋势背驰默认未要求 ≥2 中枢

- **规格**（§4.3、§4.9）：趋势背驰需 ≥2 同级别中枢；盘整背驰为 1 个中枢；无趋势时只能称盘背。
- **现状**：`ChanConfig.py:109` `min_zs_cnt=1` 默认；`BSPointList.py:168` `is_target_bsp = zs_cnt >= min_zs_cnt`。趋势/盘整区分靠 T1/T1P 两条路径，而非中枢数量阈值。
- **差距**：默认未达到规格"趋势背驰 ≥2 中枢"要求。
- **完善建议**：T1（趋势背驰）默认 `min_zs_cnt=2`；T1P（盘整背驰）限定中枢数=1；并以中枢数量作为趋势/盘整背驰的分流条件。

### 🟡 2.4 默认 macd_algo=peak，非面积；AREA 为半面积非整段

- **规格**（§4.7）：面积背驰 = 出中枢段 MACD 柱面积 < 进中枢段（上涨红柱、下跌绿柱，整段同向面积）。
- **现状**：默认笔级 `macd_algo="peak"`（`ChanConfig.py:112`），是峰值非面积；`AREA` 算法 = `Cal_MACD_half`（`Bi.py:249-289`）只累加从端点起同号柱直到变号，是**半面积**非整段同向面积；`FULL_AREA` 才是整段同向面积。
- **差距**：默认算法与规格"面积为主"不一致；AREA 语义与规格"MACD 柱面积"有偏差。
- **完善建议**：评估默认改为 `FULL_AREA` 或新增"整段同向面积"算法；明确 AREA 半面积的适用边界。

### 🟡 2.5 进/出中枢笔未校验同方向、已走完

- **规格**（§4.5、§4.10）：进/出中枢笔必须同方向、同级别、均已走完。
- **现状**：`bi_in=bi_list[begin_bi.idx-1]`、`bi_out=bi_list[end_bi.idx+1]`（`KLine_List.py:207-209`）按索引自动取，**未显式校验方向相同**，**未检查 `is_sure`**（虚拟笔可能参与判定）。`is_reverse` 参数使进/出笔分别用正向/反向半面积，方向隐含一致但无断言。
- **完善建议**：加方向断言；背驰判定要求笔 `is_sure=True`，未走完的笔不参与。

### 🟡 2.6 二买用回撤率，非"不创新高/新低"

- **规格**（§7.6）：二买 = 一买后首次反弹/回调不创新高/新低。
- **现状**：`BSPointList.py:242-243` `treat_bsp2` 用 `bsp2_bi.amp()/break_bi.amp() <= max_bs2_rate`（振幅回撤率）判定。
- **差距**：判定维度不同——代码看回撤幅度比例，规格看是否创新高/新低。
- **完善建议**：补充"不创新高/新低"作为二买的结构判定条件，回撤率作为辅助过滤。

### 🟡 2.7 盘背三形态未与 T1P/T3 联动

- **规格**（§5.2）：盘背三形态——①c 创新高+盘背+回拉不破中枢上限→3 买→演化为趋势；②c 创新高+盘背+回跌破回中枢→继续盘整；③c 未创新高+盘背→必有回跌。
- **现状**：T1P 仅标记盘背点，无演化形态判定；3 买由独立 T3A/T3B 逻辑处理，不与 T1P 联动。
- **完善建议**：盘背成立后判定回拉是否破中枢上限，分流三形态，并据此与 3 买/继续盘整/必回跌联动。

### 🟡 2.8 大周期"盘背当一买"的多周期提升缺失

- **规格**（§5.3）：大周期无标准一买时，盘背低点当大周期一买、盘背高点当大周期一卖。
- **现状**：T1 与 T1P 并列独立类型（`BSPointList.py:156-157` 都进 `bsp1_dict`），但无"大周期无标准一买则提升 T1P 为一买"的层级联动逻辑。
- **完善建议**：多周期联动——当大周期无 T1 时，将小级别 T1P 提升为大周期一买标记。

### 🟢 2.9 实现有但规格未提的扩展

- `divergence_rate > 100` 的"保送"分支（`ZS.py:171-172`）：强制判定为背驰，规格未提及。
- `out_bi_is_peak`（`ZS.py:200-214`）+ `bs1_peak`：要求出中枢笔是中枢内极值，规格未提，属额外过滤。
- `macd_algo` 多算法（PEAK/AREA/FULL_AREA/DIFF/SLOPE/AMP/RSI/量额等）：实现扩展，规格只提面积 + 黄白线两种。

## 3. 线段终结与特征序列

### 🔴 3.1 线段终结完全未结合背驰/盘背（"快了半拍"未解决）

- **规格**（§7.2、§7.4、§7.5）：仅用特征序列分型会"快了半拍"，线段终结 = 分型确认 + 背驰/盘背确认，缺一不可。
- **现状**：`Seg/SegListChan.py:64-76` `treat_fx_eigen` 纯用 `can_be_end`（特征序列分型 + 缺口时反向分型）；`Seg/` 目录无背驰/盘背逻辑。背驰仅在 `ZS/ZS.py:162` 服务买卖点，**不参与线段终结**。
- **差距**：正是规格指出的"快了半拍"问题在代码层面未解决；线段终结缺背驰/盘背这一必要条件。
- **完善建议**：在 `treat_fx_eigen` 确认分型后，追加背驰/盘背判定（趋势线段用背驰、盘整线段用盘背），两者皆成立才 `is_sure=True`。

### 🔴 3.2 无第一/第二特征序列双序列概念

- **规格**（§7.1、§10.7）：第一特征序列 = 线段未确认终结前形成；第二特征序列 = 线段疑似终结后用以二次确认，避免过早判定。
- **现状**：代码只有"同一序列的第 1/2/3 个元素"（`EigenFX.py:16` 的 `ele[0..2]`），无第一/第二特征序列概念。二次确认靠 `find_revert_fx`（`EigenFX.py:159-184`）找反向分型，且**仅在缺口时触发**（chan 默认）。
- **差距**：缺规格所述"第二特征序列"作为独立二次确认序列；现有"反向分型确认"是另一种机制，且仅缺口时触发。
- **完善建议**：引入第二特征序列——线段疑似终结后，对后续反方向笔重新构造特征序列做分型确认，作为终结的二次确认（与第一特征序列分型共同生效）。

### 🟡 3.3 第一、二元素未禁止包含（与规格相反）

- **规格**（§7.1、§10.7）：第一、二元素不能做向左包含；顶底两侧元素不能随意包含。
- **现状**：chan 默认 `treat_second_ele`（`EigenFX.py:28-36`）对一二元素**执行**包含合并；无"向左包含"禁止；`update_fx` 无顶底两侧限制。仅 `SegListChanV2.py:82-97` 禁止一二元素合并，但 V2 不是默认算法。
- **差距**：第一二元素未禁止包含，与规格相反；顶底两侧无额外约束。
- **完善建议**：默认算法对第一二元素禁止向左包含；或评估将 V2 的相关规则并入默认 chan。

### 🟡 3.4 无趋势/盘整线段分类的终结分支

- **规格**（§7.3）：趋势线段用背驰、盘整线段用盘背判定终结，不可混用。
- **现状**：代码未区分趋势/盘整线段做终结判定；线段分类（`get_multi_bi_zs_cnt` 等）用于买卖点而非终结。
- **差距**：无趋势/盘整分类的终结判定分支（依赖 3.1 的背驰/盘背接入）。
- **完善建议**：终结判定时按线段包含中枢数分流——≥2 中枢用背驰、1 中枢用盘背。

### 🟢 3.5 多版本线段算法

- `SegListChan`（默认）：特征序列分型 + 缺口时反向分型确认。
- `SegListChanV2`：一二元素不合并、统一反向分型确认、同类更极端分型/端点替代、跨度≥3 笔。
- `SegListChanDoubao`/`Doubao2`/`Doubao3`：豆包规则自实现包含/缺口/反向三笔确认。
- `SegListDef`：不建特征序列，纯按 N-2 笔极值突破。
- `SegListDYH`：按 situation1/situation2 形态判定。
- 说明：V2 在 3.3（一二元素不合并）上比默认 chan 更接近规格，但仍是另一套机制。

## 4. 完善优先级建议

按"对结构正确性影响 × 实现成本"排序，建议优先处理：

1. **🔴 线段终结接入背驰/盘背（3.1 + 3.4）**——规格核心论点，直接解决"快了半拍"，是线段与中枢/背驰三大模块打通的关键。
2. **🔴 趋势背驰 ≥2 中枢 + 盘整背驰回归中枢路径（2.1 + 2.3）**——让 T1/T1P 与规格的趋势/盘整定义对齐。
3. **🔴 黄白线算法 + 面积/黄白线双确认（2.2 + 2.4）**——补齐规格的力度判定维度。
4. **🔴 9 段扩展升级 + 扩张判定（1.3 + 1.5 + 1.7）**——中枢形态演变的核心升级规则。
5. **🔴 中枢新生（3 买触发）（1.4）**——中枢从生到死的因果链。
6. **🟡 第二特征序列双序列确认（3.2）**——线段终结二次确认机制。
7. **🟡 第一二元素包含规则（3.3）**——特征序列包含语义对齐。
